# 黄金鱼钩（zhuayu）

《黄金矿工》玩法的捕鱼小游戏。Cocos Creator 3.8 + TypeScript，目标平台微信小游戏。

当前进度：**美术素材已交付并通过验收，玩法已完成可玩实现。**

> **维护目标：只维护 Cocos 工程（`game/`）。**
> `web-preview/` 网页版已经停止开发，仅作为玩法手感与数值的对照参考保留，
> 不再接受新功能。两边画面、音频、UI 已对齐，之后只改 `game/`。

## 玩法

- 鱼钩在船下左右摆动，点击出钩，钩中鱼后自动收线
- 8 种鱼分布在不同水深，越深越大的鱼价值越高
- 鱼越大收线越慢：`max(300, 880 - size × 3.4)` px/s
- 限时 60 秒，达到目标分过关，目标分逐关递增（600 / 880 / 1160 …）

### 鱼线支点是怎么对上的

角色不是按身体中心摆放，而是按**素材里鱼竿尖的位置**反推：

1. 生成时要求竿尖完整在画面内，不贴边；
2. 抠图后用 Canny + Hough 直线检测找到竿身，沿竿方向外推得到真正竿尖；
3. 把归一化坐标写进 `princess-config.json` 的 `rodTip`；
4. 游戏里按 `tipX = x + rodTip[0] × dw` 反算节点位置，保证鱼线正好从竿尖出来。

换装时支点会跟着变（实测 x 落在 675~707、y 落在 28~49），所以鱼钩的 `origin` 是动态的，不是写死的常量。

## 画面：新中式淡彩

配色照着参考图定的，全部集中在 `game.js` 的 `PAL` / `WOOD` 常量里：

| 元素 | 色值 | 说明 |
|---|---|---|
| 水面（白天） | `rgb(178,218,210)` → `rgb(124,178,172)` | 薄荷绿，不用深蓝 |
| 天空（白天） | `rgb(205,224,230)` → `rgb(246,236,218)` | 淡青灰到米白 |
| 岸边带 | `rgb(238,232,210)` | 水线下方一条米白，手绘波浪底边 |
| 木构 | `rgb(139,106,74)` / 深 `95,70,47` / 亮 `169,133,95` | 栏杆、甲板 |
| 墨色 | `#2f3b3a` | 所有描边与文字 |

场景分层（绘制顺序在 `draw()` 里）：

1. 天空渐变 + 远山 + 塔 + 屋脊长墙（`drawScenery`，透明度 0.46~0.55，只做层次）
2. 日月星
3. 灯笼串（`drawLanterns`，绳子中点下垂 30px，7 只灯笼，光晕随夜色变强）
4. 左右上角樱花枝（`drawBlossoms`，贝塞尔枝干 + 花团）
5. 栈道栏杆（`drawRailing`，立柱 + 上下横栏，在角色身后）
6. 气泡、鱼
7. 甲板 + 岸边米白带（`drawQuay`，压住水面）
8. 鱼线、鱼钩（**必须画在栈道之后**，否则会被甲板截断）
9. 角色、特效、HUD

UI 统一用「米色牌匾」：`plaque()` 画木框 + 金线 + 两端圆钉，文字用墨色。开始 / 结算面板做成卷轴（上下两根木轴头）。

木构和岸边颜色都乘了一个 `k = 0.34 + 0.66 × 光照`，所以夜里栏杆和栈道会跟着暗下去，不会突兀地亮着。

**已知不一致**：8 张鱼的贴图和 8 张角色贴图还是之前的画风（饱和度高、偏美式卡通），和现在的中式淡彩背景不是一套。要完全统一需要按新风格重出素材。

## 画面：昼夜循环

一整天 **90 秒**，跨关卡连续，不随关卡重置。时间来自 `S.clock`（在 `update()` 里累加）。

- `lightAt(p)` 把相位映射成光照强度 0~1，天空 / 水体 / 海底 / 光柱的颜色都由它插值出来，所以是整体变暗而不是盖一层黑纱
- 太阳走**左半边**、月亮走**右半边**（`drawSunMoon`）。弧线刻意不横穿画面中央 —— 角色站在正上方，太阳一旦从她身后经过，看起来就像她手里举着个发光的球
- 星星 70 颗固定分布，透明度 = `(0.6 - light) / 0.45`，白天完全隐藏
- 日出 / 日落有暖色权重 `warmAt(p)`，把天空底部和水面顶部往橙色推
- 水下光柱裁到水线以下，夜里几乎不可见

木筏已改成**木质平台**（宽 476px，甲板 + 板缝 + 两端系缆桩 + 水面浪花），角色站在甲板上。

## 音频

网页版是 WebAudio 程序合成；Cocos 不能这么干，所以用 `tools/20_render_audio.py`
把同一套乐谱**离线渲染成 5 个 mp3**，放在 `game/assets/resources/audio/`：

| 文件 | 内容 | 时长 |
|---|---|---|
| `bgm.mp3` | C 大调 8 小节摇篮曲，88 BPM，八音盒 + 三和弦 + 低音 | 21.8s |
| `sfx_cast.mp3` | 出钩 | 0.22s |
| `sfx_catch.mp3` | 钩中鱼 | 0.50s |
| `sfx_click.mp3` | 界面点击 | 0.09s |
| `sfx_win.mp3` | 过关 / 结算 | 0.90s |

- BGM 用 `AudioSource` + `loop = true` 循环，音效用 `playOneShot` 叠加，一次抛竿 + 一次捕获同时响也不会互相打断
- 右上角 `♪` 按钮（或按 `M`）开关全部声音，状态存 `localStorage`
- 浏览器 / 小游戏要求音频必须在用户手势里启动，所以 `startBgm()` 挂在第一次点击 / 按键上

调音色的坑：最初用了大七和弦 + 随机碎音 + `2.01×` 失谐谐波，听感发飘、发诡异；现在是写死的旋律 + 正三和弦，二次谐波用干净的 `2×`。

循环接缝也踩过坑：直接渲染 8 小节首尾电平差 0.24，听得出「咔」一下。现在多渲染 4 秒尾巴，
把尾巴折回开头相加，接缝降到 0.010，听不出来。

音量不是拍脑袋定的：离线渲染实测 `bgm peak = 0.720 / rms = 0.089 / 无削波`，
所以 `Audio.ts` 里 BGM 音量取 0.45。

## 手机测试

```bash
python tools/serve.py --lan        # 绑 0.0.0.0，打印局域网地址
python tools/make_qr.py            # 生成扫码图 delivery/qa/phone-test-qr.png
```

手机和电脑连同一个 Wi-Fi，扫码或直接输地址，横屏游玩。

### 方向适配

**没有用 `@media (orientation: portrait)`。** 微信 / QQ 内置浏览器、以及开了「屏幕旋转锁」的手机，视口方向根本不会随手机改变，媒体查询会一直判成竖屏 —— 表现就是「手机已经横过来了，提示还挂着不走」。

现在改成 JS 实测视口宽高（`innerHeight > innerWidth`）判断，并且：

- 横屏 → 直接开玩，提示不出现；
- 竖屏 → 显示提示，并附一个「点这里直接玩」按钮；
- 浏览器锁死竖屏时点这个按钮 → 整块舞台 `rotate(90deg)` 铺满屏幕，游戏照常能玩，同时提示「把手机向左转 90°」；
- 转回横屏 → 兜底自动解除，恢复普通布局。

提示层上会打出实测视口尺寸（如 `当前视口 390 × 844`），方便区分「浏览器真的没转」和「判断逻辑出错」。

旋转模式下指针坐标要反算：局部坐标 `(u, v)` 映射到屏幕是 `(sh - v, u)`，`toGame()` 里做逆变换，`toScreen()` 提供正向映射给自动化测试用（`window.__toScreen__(gx, gy)`）。
