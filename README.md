# 黄金鱼钩（zhuayu）

《黄金矿工》玩法的捕鱼小游戏。Cocos Creator 3.8 + TypeScript，目标平台微信小游戏。

当前进度：**美术素材已交付并通过验收，玩法已完成可玩实现。**

> **维护目标：只维护 Cocos 工程（`game/`）。**
> `web-preview/` 网页版已经停止开发，仅作为玩法手感与数值的对照参考保留，
> 不再接受新功能。两边画面、音频、UI 已对齐，之后只改 `game/`。

## 玩法

- 鱼钩在船下左右摆动（±40°，**绳长恒定**，钩子走真正的摆弧：静止在 y≈325、两端抬到 y≈259，
  全程都在水面 y=236 以下），点击出钩，钩中鱼后自动收线
- 钩住的鱼**贴在钩爪上**（`TUNE.fishHang = 0.35`，即鱼心落在钩尖下方 0.35 个鱼高）：
  8 张鱼贴图都是 512×512、画面上边留了 6%~20% 透明，按「半个鱼高」去贴会空出一条缝
- 8 种鱼分布在不同水深，越深越大的鱼价值越高。浅水区从 y≈384 起（水面 y≈236 到鱼群之间留一条空带），
  否则鱼贴在岸边，一出钩就撞上
- 出钩 660 px/s（抛到海底约 0.7 秒）；带鱼收线按**每条鱼自己的重量** `reel`（`fish-config.json`）：
  小丑鱼 117、鲨鱼 71 px/s。实测从各自半深的位置拉上来：小丑鱼 0.57 秒、神仙鱼 1.17 秒、
  鳐鱼 / 鲨鱼 2.33 秒 —— 小鱼一拽就上来，大货要拉几秒
- 限时 60 秒，达到目标分过关，目标分逐关递增（600 / 880 / 1160 …）

## 八条鱼的性格

数值全在 `resources/config/fish-config.json`，代码里没有写死任何一条鱼的脾气。
每条鱼由四个数定义：`baseSpeed`（游多快）、`pattern`（怎么游）、`wave`（纵向摆幅）、
`reel`（拉起来多沉）。**没有「只是换了张图」的鱼** —— 光靠大小和分值区分，
八条鱼在手里就是同一条鱼。

| 鱼 | 分 | 游速 | 游法 | 收线 | 一句话 |
|---|---|---|---|---|---|
| 小丑鱼 | 20 | 110 | dart | 0.57s | 一惊一乍地窜，趁它慢下来的那半秒下手 |
| 蓝色热带鱼 | 25 | 155 | dart | 0.45s | 全场最快，游起来了基本打不中，等它停 |
| 金鱼 | 30 | 52 | cruise | 0.73s | 匀速直游、上下摆得开，新手的第一口肉 |
| 神仙鱼 | 40 | 78 | sweep | 1.17s | 优雅地上下巡游，横速稳定所以好瞄，但不算轻 |
| 河豚 | 50 | 42 | glide | 1.55s | 慢得离谱，可一钩就鼓成球，拖起来比看着沉得多 |
| 黄金锦鲤 | 150 | 96 | burst | 1.75s | 平时懒洋洋，隔几秒窜一段 —— 那一段里出钩必空 |
| 鳐鱼 | 100 | 40 | glide | 2.35s | 贴着海床滑，几乎不躲，代价全在「拉」上 |
| 鲨鱼 | 200 | 62 | burst | 2.35s | 慢巡 + 大冲刺，最难瞄也最难拉，一钩抵十条小丑鱼 |

五种游法（`Fish.targetMul()`）：

- `cruise` 匀速直游 —— 速度恒定，纯拼准头
- `dart` 走走停停 —— 速度在 0.30~1.35 倍之间按正弦脉动（3.2 rad/s）
- `sweep` 优雅巡游 —— 横速恒定，纵向正弦摆幅大（神仙鱼 16px）
- `glide` 贴底滑翔 —— 几乎不躲，靠「沉」来收成本
- `burst` 间歇突进 —— 3.6 秒一个循环，其中 0.7 秒跑 2 倍速

速度倍率是**平滑靠拢**目标的（`dt × 4.5`，约 0.22 秒到位），不是直接赋值：
直接跳变的话，冲刺那一下看着像被瞬移了一格。

收线速度也在这里定，不再按体型公式算。之前是 `max(150, 500 - size × 1.9)`，
两条同样是 78 宽的鱼收起来一模一样，而「体型」其实只是一个美术属性。
现在 `reel` 是独立数值：河豚（50）比体宽 144 的鳐鱼（71）还沉，因为它是鼓起来的球。

> 水位下移 46px 之后，钩子待机位置从 y=277 落到 325，收线行程整体短了约 48px。
> 所有 `reel` 都是**按实测耗时反推重算过**的（`v_new = v_old × d_new / d_old`），
> 表里的秒数没有被这次改版改掉。同理 `TUNE.reelMin` 从 80 降到 45 ——
> 还按 80 兜底的话，河豚 / 鲨鱼 / 鳐鱼会被一起拔到 80，耗时变快、分量排序也乱了。

越沉的鱼被钩住后扑腾得越凶（`Fish.followTo()`）：鲨鱼会明显左右甩，小丑鱼几乎只是被拖走。
慢收线的这两三秒里如果画面完全静止，那就不叫「拉大鱼」，叫「等进度条」。

## 道具（三种增益 / 两种负面）

代码在 `Props.ts`，参数全在 `GameConfig.ts` 的 `PROP` / `BEAST`。

| 道具 | 表现 | 效果 | 时长 |
|---|---|---|---|
| 雪花 · 减速 | 漂着的圆徽章 | 全场鱼速 ×0.35（**钩子和收线不受影响**），顶部出现状态条倒计时 | 7 秒 |
| 暂停 | 漂着的圆徽章 | 全场冻结：鱼、钩、计时、昼夜、气泡一起停，圆牌倒数后自动继续 | 3 秒 |
| 加时 | 漂着的圆徽章 | 时间 +10 秒（上限 120 秒，防止连吃加时把一关拖太长） | 即时 |
| ☁ 大雾（负面） | **章鱼**，从屏幕外游进来 | 水线以下糊成一片，鱼只剩淡影、分不清哪条。**不拦出钩，也不改任何数值**，但你看不清就没法瞄 | 3 秒 |
| ✂ 断线（负面） | **剑鱼**，从屏幕外游进来 | 鱼线和钩子一起消失，这 3 秒内点屏幕不出钩；最后 0.8 秒线从竿尖往下长回来 | 3 秒 |

### 水里有两套视觉语言，故意的

- **增益 = 死物。** 圆徽章上下浮动 + 左右慢漂（振幅 40~72px、周期 9~12 秒），
  比鱼慢一个数量级，所以还是「水里飘着的一个宝贝」而不是一条鱼。
  漂移振幅会被「出钩扇形里还剩多少宽度」再收一次，贴着边缘刷出来的就少晃一点 ——
  不能让它摇到摆幅够不着的地方。
  **徽章上不写名字**：雪花 / 双竖条 / 时钟三个图标已经说清楚了，再挂一块「减速 / 暂停 / 加时」
  的小牌匾，水里就多出一排字，比鱼还抢眼。
- **负面 = 活物。** 章鱼和剑鱼从屏幕外游进来，随机方向、随机深度，横穿鱼塘。

为什么负面要做成活物：静止的徽章一眼就能躲开，等于白送一个「别点它」的提示。
活物会在鱼群里穿来穿去 —— 你瞄的那条鱼背后正好游过一只章鱼，这一钩就有风险了，
风险和收益这才落在同一根线上。

**但负面生物头顶挂一小块黄色三角警示牌**（26×21，黄底 + 深棕边 + 感叹号）。仔细看能认出来，忙起来会看漏。
完全伪装成普通鱼看着刺激，实际是让玩家赌：赌输了只会觉得被耍，不会觉得自己手滑。
牌子只在「还在水里游」的时候挂 —— 钩中了就收起来，否则它正好卡在钩爪和鱼背之间，把咬合挡得看不见。

### 负面道具为什么要存在

不是为了惩罚玩家，而是让水里多一个要绕开的东西。

两条硬规则：

- **钩到就吃亏，但只在「收上来」那一刻结算。** 和增益道具完全一致：钩尖碰到只是挂住，
  得先把它拖到竿尖。所以吃到一个负面道具，代价是「浪费一钩 + 后续 3 秒」，不是当场就崩。
- **只动「看得见」和「能不能出钩」，不动数值。** 大雾期间鱼照游、计时照走、钩照出，
  只是看不见；断线期间除了不能出钩，其它照旧。负面道具一旦开始改鱼速 / 分数，
  玩家会觉得是游戏在耍赖，而不是自己钩错了。

大雾的浓度是一层底板 + 三层雾团叠出来的（`Props.layoutFog`）：

- **底板薄纱 0.78（alpha 199）**，从码头立面下沿（`waterTop + 22`）往下铺，不盖甲板和公主 ——
  雾是水里的东西，糊住她的脸既不真实也没信息量。这一层单独就把鱼的颜色和花纹吃掉大半，
  只剩一团模糊的暗影；
- **三层雾团各画一次**，每团由 3 个偏心椭圆组成（单团 alpha 38~60）：最慢的一层 7px/s、
  最快的一层 27px/s，方向还不一样，所以雾是在「滚」而不是整块平移。
  三团叠上的地方合成浓度 0.95+，那片水里连影子都没有；只叠一团的缝隙留 0.84 左右，
  能隐约看出「那儿有条鱼」，但认不出是哪条。

**为什么改成「画一次 + 拨透明度」**：原来是每帧 `clear()` 再重画 48 个椭圆。
一是贵（60fps 下每帧上百次 fill），二是浓度上不去 —— 为了控成本只能把单块透明度压到 0.1，
整屏薄纱也只敢给 0.76，结果鱼连花纹都看得清，等于「加了层滤镜」，挡不住任何东西。
现在一次画死，淡入淡出交给 `UIOpacity`、漂移只挪三个雾团节点（每帧 3 次 `setPosition`），
省下来的预算全部换成浓度。上沿还做了 70px 的渐变，否则水面上会像拉了一块白板。

断线的表现分三段（`Hook.breakLine` / `Hook.update`）：

1. `rope = 0` → 线消失，钩爪 `active = false` 一起藏掉（只清绳子的话钩爪会缩在竿尖上，
   看起来像「钩子还在、线变短了」）；
2. 前 2.2 秒什么都不长，顶部状态条写「鱼线修复 x.xs」；
3. 最后 `PROP.regrow = 0.8` 秒里绳子从 0 长回 `idleRope`，线到位后钩爪才重新出现。

断线期间点屏幕会飘一行「鱼线修复中」（500ms 节流）。没有这个反馈的话，玩家只会看到
「点了没出钩」，当成卡了或者没点准，然后一直连点 —— 那才是真正的负面体验。

### 生物的贴图

章鱼和剑鱼是用 ImageGen 按鱼群风格生成的（参考图给的是河豚那张），
成品 512 方图、透明背景，和现有 8 种鱼同一套比例与留白。

坑在「假透明」：ImageGen 返回的是 **RGB**，请求的透明背景会被画成 `#fff` / `#e6e6e6`
交替的棋盘格，直接当贴图用会带着格子。`tools/26_matte_props.py` 负责抠：

- 判据不是「接近纯白」，而是「中性浅色 + 与四边连通」。剑鱼腹部是带蓝的浅灰，
  按纯白判会把它啃掉一块；按中性灰判，棋盘格和鱼身就分得开。
- 只认**与边框连通**的那一片，所以鱼身内部的浅色斑块（吸盘、高光）会保留。
- 抠完做反预乘去白边，再缩进 512 画布，留白对齐到 `452 / 512`。

```bash
python tools/26_matte_props.py <生成的原图.png> octopus
```

两个目录（`assets/images/fish` 和 `game/assets/resources/images/fish`）会一起写，
`.png.meta` 也一并生成（uuid 两条路径共用同一个，别让 Cocos 认成两份资源）。

### 生物的三个数值约束

改 `BEAST` 之前先看，这三个是踩过坑的：

1. **`size` 是「贴图整幅」的宽度，不是鱼身宽度。** 512 方图里上下有留白（章鱼顶空 11%、
   剑鱼顶空 18%），内容只占八成左右。所以数值要比看着的大一圈：112 / 140，
   才能在鱼群里一眼跳出来，而不是和河豚混在一起。
2. **`warnY` 要逐个配，不能统一取 0.5。** 两种贴图的留白不一样，统一取 0.5 会让警示牌
   要么压进头顶、要么悬在半空。它是警示牌**中心**的 y（占显示高度的比例）。
3. **`speed` 必须保证「能自己游出屏幕」。** 生物的离场方式是游出可见区域，
   `BEAST_LIFE = 34` 只是兜底。最宽的 19.5:9 屏可见宽度约 1560，
   章鱼 (1560+112)/62 ≈ 27s、剑鱼 (1560+140)/105 ≈ 16s，都留了余量。
   早先给章鱼 30 想表现「慢吞吞」，结果横穿一屏要 46s，会在画面中间凭空消失。

生物不套下面徽章那套「出钩扇形」约束：它是活物，游到哪儿算哪儿。
有些个体可能整段都游在摆幅够不着的地方 —— 那也没关系，它本来就不是给你钩的。

### 徽章道具的三条规则

1. **左右漂，但只在能钩到的范围里漂。** 存活 9 秒，最后 1.6 秒打闪提示。
   横向是正弦往返（振幅 40~72px、周期 9~12 秒），纵向是 7px 的小浮动 ——
   钉死不动的话，整片水面只有鱼在动，徽章看着像背景贴图。
   用正弦而不是匀速：匀速撞到端点会「啪」地掉头，像弹球；正弦两端速度归零，才像水里飘的东西。
   生成时会把振幅按该深度下扇形剩下的宽度再收缩一次，所以贴着边缘刷出来的晃得少，
   居中的晃得开 —— **不能让它摇到摆幅够不着的地方**，否则玩家只能看着它在那儿晃。
2. **生成位置在「竿尖往下的出钩扇形」里。** 钩子只能沿当前摆角（±40°）出钩，
   按可见宽度均匀撒的话，两侧的道具玩家怎么等都够不着。`PROP.spread = 0.8`
   就是把这个扇形收窄到 ±32°（贴 40° 极限的位置要等摆到端点才打得到，手感很差），
   再按 `x = 竿尖x + tan(θ) × 深度差` 反推坐标。换了角色竿尖会动，`Props.setOrigin()` 要跟着更新。
   QA 里 `&proptest=1` 会刷 200 个道具验证 `outOfCone=0`，再让 60 个道具漂 6 秒验证 `outCone=0`。
3. **深度卡在 y ∈ [500, 620]。** 待机时钩尖在 y≈325 来回摆，徽章再浅就会被晃来晃去的空钩
   顺手钩走，玩家还没瞄准就白捡一个效果；下界 620 是海床（668）往上留的一条带，再深就陷进沙子里。
   生物放宽到 `BEAST_Y = [444, 610]`：活物本来就在水里乱窜，锁死在深水区反而不像鱼。

### 道具怎么被钩住（两种形态共用一套）

徽章和生物都能被钩住，表现和钩鱼完全一样：钩尖撞上 → 挂在钩爪下面 → 收线带回来 →
**到竿尖的那一刻效果才生效**，同时播 `sfx_prop`、飘字、涟漪。

所以一钩只能带一样东西，`Hook.carryingProp` 和 `Hook.carrying` 互斥：

- `Hook.canLatch()` 要求「钩子在水里（`state !== 'aim'`）且两手空空」；
- 挂上之后 `state` 直接转 `retract`，和钩住鱼是同一套收线逻辑，但用道具自己的收线速度
  （`PROP.reelBadge = 147`、章鱼 106、剑鱼 87 px/s）。原来这里走的是「空钩回收」的 607 px/s，
  一枚徽章从深水拽上来只要 0.3 秒 —— 捞东西快得像钩了个气泡，完全没有分量；
- 判定在 `GameRoot.update` 里做（`props.find()` 只找不摘，`props.detach()` 才把它从刷新列表里摘出来），
  这样 `Props` 不会再去推进一个已经被钩子接管的东西；
- 换关 / 重开时 `resetProps()` 会先把手上那枚取下来 `destroy()`，
  否则它已经从列表里摘掉了，`Props.clear()` 扫不到它，节点会留在场景里。

**代价是实打实的**：抓一个道具要 0.7 秒左右，这段时间钩不到鱼。
所以「先捞道具还是先钩鱼」是有取舍的选择，而不是无脑白拿。

挂在钩爪上的位置（`PropItem.followTo()`）：

- 徽章：中心放在钩尖下方 `PROP.size × 0.55` 处。钩爪本身是从钩尖往下画的（最低到 -13px），
  中心对齐钩尖的话爪子和徽章会叠成一坨，往下挪半个身位才像「叼着」。
- 生物：和鱼共用 `TUNE.fishHang`（0.35 个身位），钩爪正好咬进背鳍。

刷新节奏：开局 3.5 秒刷第一个，之后间隔 6~8.5 秒，同屏最多 3 个 —— 一关 60 秒大约 8 个。

两条容易写错的细节：

- **只在「刷出一个」之后重新计时。** 到期消失、被钩走都不重置 `gap`。重置的话实际周期会变成
  「寿命 9 秒 + 间隔 8 秒」= 17 秒一个，一关到头来只有 5 个 —— 这是实测出来的，不是推算
  （`&spawnrate=1` 跑 55 秒，改之前 5 个，改之后 7 个）。
- **满员时 `gap` 不递减。** 否则它会一路减成负数，等名额一空就立刻弹一个，变成「刚钩走马上又来」的连发。

同屏给 3：生物要横穿一屏（十几秒），名额给少了会被它整段占住，那期间玩家眼前一个可捞的东西都没有。

权重 减速 26 / 加时 24 / 暂停 12 / 大雾 21 / 断线 17，负面合计 38%。
再叠一道**防连空**：连着刷出 3 个增益之后，下一只强制是负面（`Props.rollKind()`）。
纯概率下 60 秒一关里一只负面都不出的概率有 3.5%，但玩家只会记得「这局一条怪鱼都没有」，
不会去算概率。两道保险叠起来实测负面占 43~50%（`&spawnrate=1` 55 秒：7 个里 3 只）——
一半道具都是坏东西会让人不敢捞，43% 大约是「水里总能看见一只怪鱼」的程度。

暂停期间输入全部吃掉（`pointer()` 和 `action()` 都拦），避免恢复的瞬间被连点吃掉一次出钩。
大雾 / 断线同样走「暂停时一起冻结」（`GameRoot.update` 在 `pauseT > 0` 时提前 return），
所以暂停期间这几个倒计时都不会偷偷走掉。

## 屏幕适配（FIXED_HEIGHT）

工程按 `project.json` 的 `fitHeight` 走 **FIXED_HEIGHT**：高度恒为 720，**宽度随屏幕比例变化**。
`GameConfig.ts` 里的 `VIEW` 就是当前可见区域（`left / right` 是设计坐标下的左右边界），
`syncView()` 在启动和窗口尺寸变化时刷新它。

凡是「铺满屏幕」的东西都按 `VIEW` 铺，不能写死 `DESIGN.w`：

| 位置 | 用到的量 |
|---|---|
| 背景天空 / 水体 / 光柱 / 海底 | `VIEW.left - OVER` ~ `VIEW.right + OVER`（`OVER = 420`，给超宽屏留余量） |
| 栏杆 / 甲板 / 岸边带 / 灯笼 / 樱花枝 | `VIEW.left` ~ `VIEW.right` |
| 鱼群出生与左右换边 | `VIEW.left` / `VIEW.right` |
| HUD 左侧牌匾、换装按钮 | `VIEW.left + …` |
| HUD 时间牌匾、静音按钮 | `VIEW.right - …` |

**踩过的坑**：`view.setDesignResolutionSize()` 只改 view 里的设计分辨率，
**不会**回头改 Canvas 节点的位置和相机的 `orthoHeight`。原来这里写的是 `SHOW_ALL`，
和工程的 `FIXED_HEIGHT` 打架，Canvas 与相机停在旧的可视尺寸上 ——
表现就是画面整体偏一边、另一侧露出相机的**黑底**，鱼游到还在水里的时候就凭空消失了。
现在 `GameRoot.fitToScreen()` 会手动把 Canvas 节点、`UITransform`、相机 `orthoHeight` 对齐一遍，
并且把相机的清屏色设成水色（`Background.setCamera()`），即使有没盖到的像素也不会是黑的。

`tools/cocos-preview/main.js` 里 `render()` 会把 Canvas 节点自身的位置抵消掉 ——
那是「画布在屏幕上的位置」，不是内容偏移，不抵消的话整幅画面会被挪走。

### 竖屏：手机浏览器默认就是竖的

网页**没法**强制改屏幕方向（`screen.orientation.lock()` 只在全屏状态下、且只有 Android Chrome 支持，
iOS Safari 完全不支持），所以竖屏只能靠提示 + 玩家手动转。

`Orientation.ts` 的 `OrientationGate` 就是这一层：竖屏时盖一块米色牌匾，
写「请把手机横过来 / 横屏才能铺满整个鱼塘」，并暂停玩法（`GameRoot.update` 直接 return，
点击 / 空格也一律吃掉）。玩家把手机横过来触发 resize 后，`check()` 发现已横屏就自动收起、继续玩。

牌匾上的「全屏并横屏」按钮只在浏览器里出现（`sys.isBrowser && screen.supportsFullScreen`）：
点它先 `screen.requestFullScreen()`，再试 `screen.orientation.lock('landscape')`。

竖屏下可见宽度只剩 `720 × 屏宽/屏高`（390×844 的手机约 333），HUD 会挤成一团、鱼也没地方游，
所以竖屏不做「硬塞进去玩」的降级。截图见 `delivery/qa/portrait-gate.png`。

> **微信小游戏不需要这一层**：打包时把 `deviceOrientation` 设成 `landscape`，平台会自己转屏。

### 顶部画幅：水位定在 y=236

公主站在水线上，所以「水线在哪」就是「顶部那块有多大」。原来 `waterTop = 190`、
公主 168px（占画面 23%），她头顶离上边框只剩 28px，整个人缩在画面顶边，
像个小摆件，上面一排灯笼串和栏杆也挤成一条。

现在 `waterTop = 236`、`princessH = 204`：顶部留白 236px（33%），公主 204px（28%），
帽子离上边框 47px，抬眼就是「站在岸边的主角」。

代价与联动（这些必须一起改，否则画面会断层）：

- **水变浅了 46px**（236 → 海床 668，深 432）。深水区的鱼和道具不用动 ——
  海床没挪，它们本来就不受水位影响；只有浅水区四个鱼种往下让了 45px，
  免得鱼贴着空钩刷出来（`ZONE`）。
- **栏杆 / 甲板全部改成由 `TUNE.waterTop` 反推**
  （`Scenery.drawBack` / `drawQuay`：码头顶面 `-32` → `+6`，立面到 `+16`，
  栏杆再往上 `-8 / -34`）。原来这几个是写死的 184 / 199 / 210，水位一挪就会
  「水降下去了、栏杆还悬在半空」。
- **顶部不再挂东西**。原来横跨整个天空的灯笼串和左右上角的樱花枝全删了：
  灯笼串正好压在公主帽子上方一条、樱花枝整个躲在 HUD 卡片后面，
  既挡视线也没有信息量。暖光改由栈道两侧的灯笼柱提供，位置更低、更像岸边。
  柱子只在**够宽**的屏上画右边那根（`VIEW.right - 400` 要离开公主 160px 以上），
  4:3 平板上右侧那根会怼到鱼竿旁边，索性不画。
- **钩子必须跟着沉下去**。待机绳长从 240 加到 280 —— 不是想让它更深，是被摆幅逼的：
  钩子走 ±40° 的摆弧，端点高度 = `竿尖y + 绳长 × cos40°`。公主放大后竿尖落到 y≈45
  （原来 37），水位又降了 46，绳长低于 282 时钩子摆到端点会**冒出水面**。
  最终静止在 y≈325、两端抬到 y≈259，全程在水下。
- **收线行程跟着短了约 48px**，所以每条鱼的 `reel` 都按实测耗时反推重算了一遍，
  见「八条鱼的性格」下面那段说明。
- **状态条挪到公主右侧**（`StatusPill.draw`）。她放大之后头顶正好在画面正中，
  牌匾原来贴着顶部居中摆，一挂「大雾 / 减速」就盖住她的帽子和脸。
  右边界留 210px 给倒计时牌匾，窄屏（4:3 平板可见宽 960）也不会撞上。

### 鱼线支点是怎么对上的

角色不是按身体中心摆放，而是按**素材里鱼竿尖的位置**反推：

1. 生成时要求竿尖完整在画面内，不贴边；
2. 抠图后用 Canny + Hough 直线检测找到竿身，沿竿方向外推得到真正竿尖；
3. 把归一化坐标写进 `princess-config.json` 的 `rodTip`；
4. 游戏里按 `tipX = x + rodTip[0] × dw` 反算节点位置，保证鱼线正好从竿尖出来。

换装时支点会跟着变（实测 x 落在 675~707、y 落在 38~63），所以鱼钩的 `origin` 是动态的，不是写死的常量。

### 礁石带为什么单独一个模块

`Reef` 分两层画，成本才压得住：

- **静态层**（珊瑚 / 礁石 / 贝壳 / 海星，一次约 90 个 fill）只在**光照变化**时重画
  （阈值 0.012），白天一次都不重画；
- **海草层**按 20fps 重画（6 条草 × 14 段），因为它要随水流摆。

礁石只贴在可见区域的左右两端 + 底部，中间留空：鱼要横穿画面，中间塞满珊瑚会把鱼挡住，
也看不出「水有多深」。

海草那一条踩过两次坑：先用「逐段描边」拼茎，接缝一到粗细变化就像竹竿一节一节的；
改成**填充带**（左缘上去、右缘下来，一个 `fill` 画完）之后边缘才光滑。
叶缘再加一个沿高度的宽度起伏（`1 + 0.3 sin(t·8.5)`），才不会是一条笔直的绿带子。

### HUD 从木牌匾换成卡片

原来 HUD 是「米色木牌匾 + 金线 + 两端圆钉」的新中式，压在亮蓝天空上又土又闷。
现在是**绿胶囊 + 白色圆角卡**（`Hud.card`：白底 + 浅绿描边 + 一层软阴影），
文字固定用墨色 —— 牌匾本身不透明，不用再跟着昼夜换色，`Hud.setLight` 已删除。

三条布局约束（改宽度前先看这三条）：

- 左下一排总宽必须收在 **192px 以内**：换装按钮钉在 `VIEW.left + 200`，再宽就盖住它；
- 时间卡贴 `VIEW.right`，不是 `DESIGN.w` —— FIXED_HEIGHT 下宽屏比 1280 宽；
- 目标卡里的进度条和时间条画在**独立的 `barNode`** 上，只在刻度变化时重绘。

## 画面：昼夜循环

一整天 **90 秒**，跨关卡连续，不随关卡重置。时间来自 `S.clock`（在 `update()` 里累加）。

- `lightAt(p)` 把相位映射成光照强度 0~1，天空 / 水体 / 海底 / 光柱的颜色都由它插值出来，所以是整体变暗而不是盖一层黑纱
- 太阳走**左半边**、月亮走**右半边**（`drawSunMoon`）。弧线刻意不横穿画面中央 —— 角色站在正上方，太阳一旦从她身后经过，看起来就像她手里举着个发光的球
- 星星 70 颗固定分布，透明度 = `(0.6 - light) / 0.45`，白天完全隐藏
- 日出 / 日落有暖色权重 `warmAt(p)`，把天空底部和水面顶部往橙色推
- 水下光柱裁到水线以下，夜里几乎不可见

### 码头（公主站的平台）

参考图里的平台之所以像「站人的地方」而不像「一条挡水的木边」，靠三件事：

- **面积**：顶面 38px 深（`waterTop - 32` → `waterTop + 6`），四块横板；
- **结构**：四块板各有自己的色阶、横缝带一条反光（只画深线远看就是划痕）、
  板端竖缝逐行错开、木纹压到 alpha 14、四个节疤；前沿再收 10px 深色立面 + 一排板端线；
- **配景**：五根系缆桩 + 垂下的麻绳、一只木桶、一盘绳圈，每个都先铺一层投影
  （没有投影，它们就是贴在木板上的贴纸）。

三条硬约束，改之前先看这三条：

1. **顶面前沿必须压在公主的脚线上**（`waterTop + 6` 就是 `feetY`）。立绘的内容底边
   正好落在 `feetY`：前沿高过脚，人像踩在半空；低过脚，脚就掉进水里。
   第一版把立面做到 22px，她的脚正好卡在立面中间 —— 平台一下就假了；
2. **立面下沿不过 `waterTop + 16`**：钩子摆到两端时钩尖抬到 y≈259，立面再深，
   钩子就浮出水面变成一把悬在空中的钩子；
3. **栏杆的底栏要一路压到顶面**：留一条缝，缝里会漏出湖水，横贯画面一条青线。

栏杆是**远处**的岸边栏杆：木色往湖水青灰里混了 30%（空气透视），柱子间距从 176 放到 264。
它原来和码头共用同一套木色，两条横向木带叠在一起糊成一片「木墙」，码头就显不出来了。


## 音频

网页版是 WebAudio 程序合成；Cocos 不能这么干，所以用 `tools/20_render_audio.py`
把同一套乐谱**离线渲染成 6 个 mp3**，放在 `game/assets/resources/audio/`：

| 文件 | 内容 | 时长 |
|---|---|---|
| `bgm.mp3` | C 大调 8 小节摇篮曲，88 BPM，八音盒 + 三和弦 + 低音 | 21.8s |
| `sfx_cast.mp3` | 出钩 | 0.22s |
| `sfx_catch.mp3` | 钩中鱼 | 0.50s |
| `sfx_click.mp3` | 界面点击 | 0.09s |
| `sfx_win.mp3` | 过关 / 结算 | 0.90s |
| `sfx_prop.mp3` | 道具收上来（上行三连铃音 + 高频点缀） | 0.72s |

`sfx_prop` 刻意做得比 `sfx_catch` 更高更亮：两个都是「叮咚」，音区不拉开的话玩家分不清
这一钩捞到的是鱼还是道具。渲染需要 `pip install numpy scipy lameenc`。

- BGM 用 `AudioSource` + `loop = true` 循环，音效用 `playOneShot` 叠加，一次抛竿 + 一次捕获同时响也不会互相打断
- 右上角 `♪` 按钮（或按 `M`）开关全部声音，状态存 `localStorage`
- 浏览器 / 小游戏要求音频必须在用户手势里启动，所以 `startBgm()` 挂在第一次点击 / 按键上

调音色的坑：最初用了大七和弦 + 随机碎音 + `2.01×` 失谐谐波，听感发飘、发诡异；现在是写死的旋律 + 正三和弦，二次谐波用干净的 `2×`。

循环接缝也踩过坑：直接渲染 8 小节首尾电平差 0.24，听得出「咔」一下。现在多渲染 4 秒尾巴，
把尾巴折回开头相加，接缝降到 0.010，听不出来。

音量不是拍脑袋定的：离线渲染实测 `bgm peak = 0.720 / rms = 0.089 / 无削波`，
所以 `Audio.ts` 里 BGM 音量取 0.45。

## 数值

鱼类数值唯一来源是 `assets/images/fish/fish-config.json`；
Cocos 运行时读的是 `game/assets/resources/config/fish-config.json`，
它是同一份数据按 1.2 倍放大后的副本（Cocos 里鱼看起来比网页版大一圈），**改尺寸要两边一起改**。

体型拉开档次：小丑鱼 60 → 鲨鱼 150（运行时 72 → 180），越大越贵。
**收线快慢不再跟体型挂钩**，由每条鱼自己的 `reel` 决定（见「八条鱼的性格」）——
同样是 78 宽的河豚和蓝色热带鱼，一个 0.45 秒一个 1.55 秒，体型说明不了这件事。

玩法调参在 `game/assets/scripts/GameConfig.ts` 的 `TUNE`（**只改这里**）。

目标分不是拍脑袋定的：用自动化脚本模拟「会瞄准的玩家」跑满 60 秒，实测得分 1615（28 次出钩），据此把第 1 关目标从初版 240 上调到 600。
出钩、收线改慢之后用 `tools/cocos-preview/qa.html?balance=1` 复测（会瞄准的玩家跑满 60 秒）：
5 局得分 2320 / 2545 / 2835 / 2960 / 2960，出钩 46~51 次。首关 600 分余量充足，所以目标分没动。

加道具之后复测（道具会改变随机数序列，鱼群分布不同，属正常波动）：
3 局 `score=2520 / 2645 / 2975`，出钩 44~49 次，仍然远高于首关 600。出钩 / 收线耗时没有变化
（`SIM empty cast=0.60s | shark cast=0.40s reel=1.68s | clownfish cast=0.13s reel=0.25s`）。

道具自身的效果用 `?proptest=1` 验证：

```
PROP time +10s | fish 1s normal=40px slow=14px | pause1s dtime=0.00 left=2.00
     | after dtime=0.48 paused=false | spawn200 outOfCone=0 badDepth=0
     | drift moved=53/60 ampMax=72 outCone=0 | mix beast=46% maxDryRun=3
     | carry slow 0.73s slowT=7.0 held=no
```

`pause1s dtime=0.00` 是关键：暂停期间计时真的停住了，不是只把鱼冻住。
`drift outCone=0` 证明徽章漂了 6 秒也没漂出出钩扇形（`moved=53/60` 是有的徽章漂得少、
位移不到 2px，属于贴着扇形边缘刷出来的那批，正常）。
`mix beast=46% maxDryRun=3` 是抽签比例的裸统计（不走自然节奏），验证防连空最多连空 3 个。
`carry slow 1.57s` 是抓一个道具的完整耗时（出钩 + 收线），效果在收上来的那一刻才生效。
它是「先捞道具还是先钩鱼」这个取舍的全部重量 —— 0.7 秒的时候这个选择几乎不存在。

八条鱼的性格用 `?fishtest=1` 逐条实测（游速区间 / 纵向摆幅 / 收线耗时）：

```
FISH sig=8/8 clownfish v=44~136 amp=6/6 reel=0.57s | goldfish v=52~52 amp=11/11 reel=0.73s
  | blue_tang v=63~193 amp=5/5 reel=0.45s | pufferfish v=42~42 amp=4/4 reel=1.55s
  | angelfish v=78~78 amp=15/16 reel=1.17s | ray v=40~40 amp=9/9 reel=2.33s
  | shark v=28~119 amp=3/3 reel=2.33s | golden_koi v=43~177 amp=8/8 reel=1.73s
  | badge reel=2.33s beastReel=106/87px/s
```

`sig=8/8` 是把「游法 + 实测摆幅 + 鱼名」拼成的指纹，八条各不相同才算通过 ——
防止八条鱼最后配成了同一个脾气。`v=28~119` 这种区间是 burst 的两档速度，`v=52~52` 是 cruise 匀速。

两个负面道具用 `?negtest=1` 验证（只跑数值，不渲染）：

```
NEG brokenFires=0(want 0) | rope@0.5s=0(want 0) | breakLeft=0.00(want 0)
  | ropeAfter=280(want 280) | firedAfter=true(want true)
  | fogFires=true(want true) | fogLeft=3.00(want 3.00)
```

`brokenFires=0` 是断线的核心断言：3 秒内连点 30 帧，一次钩都出不去。
`fogFires=true` 反过来证明大雾**没有**碰出钩逻辑 —— 它只挡视线。

负面生物的游动与离场用 `?beasttest=1` 验证（`&vw=1560` 可以一并验宽屏）：

```
BEAST isBeast=y,y | outsideX=y,y | swam=y,y | stillInside=y,y | leftAlive=0
```

`leftAlive` 只数这一次自己 spawn 的那两只（不是 `list.length`）：断言期间逐帧压住 `gap`，
否则生物离场会触发排队，30 秒里又刷出新的，清点就永远对不上。

一关到底刷几个、几个是坏东西，用 `?spawnrate=1` 跑 55 秒自然节奏：

```
RATE 55s total=7 beast=2 (29%) maxDryRun=3 | cfg gap=6~8.5 maxAlive=3
```

`outsideX=y,y` 是「从屏幕外游进来」，`swam=y,y` 是「真的在横着游」，
`leftAlive=0` 是「30 秒后自己游出去了」—— 这一条专门防「游到画面中间凭空消失」：
早先章鱼给 30px/s，横穿一屏要 46 秒，兜底寿命 22 秒，结果它每只都在画面中间蒸发。

道具相关的参数：

- `&props=1` 同屏摆出五种道具（减速 / 暂停 / 加时 / 章鱼 / 剑鱼），核对外观 —— `delivery/qa/prop-clean.png`

- `&proptest=1` 只跑数值：加时秒数、减速前后鱼 1 秒走的距离、暂停 1 秒内计时变化、
  刷 200 个道具的可达性、徽章漂移是否漂出扇形、负面占比、以及「钩住 → 收上来 → 效果生效」的闭环耗时
- `&fishtest=1` 只跑数值：八条鱼逐条实测速度区间 / 纵向摆幅 / 收线耗时，外加一枚徽章的收线耗时

### 方向适配

**没有用 `@media (orientation: portrait)`。** 微信 / QQ 内置浏览器、以及开了「屏幕旋转锁」的手机，视口方向根本不会随手机改变，媒体查询会一直判成竖屏 —— 表现就是「手机已经横过来了，提示还挂着不走」。

现在改成 JS 实测视口宽高（`innerHeight > innerWidth`）判断，并且：

- 横屏 → 直接开玩，提示不出现；
- 竖屏 → 显示提示，并附一个「点这里直接玩」按钮；
- 浏览器锁死竖屏时点这个按钮 → 整块舞台 `rotate(90deg)` 铺满屏幕，游戏照常能玩，同时提示「把手机向左转 90°」；
- 转回横屏 → 兜底自动解除，恢复普通布局。

提示层上会打出实测视口尺寸（如 `当前视口 390 × 844`），方便区分「浏览器真的没转」和「判断逻辑出错」。

旋转模式下指针坐标要反算：局部坐标 `(u, v)` 映射到屏幕是 `(sh - v, u)`，`toGame()` 里做逆变换，`toScreen()` 提供正向映射给自动化测试用（`window.__toScreen__(gx, gy)`）。
